# Coopanion v0.2.34

**Upstream fix merged: a rejected image request is retried once without its pictures**

## Brought in from upstream

- **Image fallback**: when a request carrying pictures is refused (400 / 413 / 422, and not a context overflow), the pictures are dropped and the request is sent once more; only an accepted retry records that this endpoint takes no pictures, and the text gains an `imageLeftOut` line. Before this, such a batch failed outright and the picture stayed "not yet delivered", so every later batch carried it and failed in turn.
- When the retry fails too, the error carries both attempts, nothing is remembered, and Core handles it as before.
- New tests run a local fake service across the four protocols: 400 first then success, later requests carrying no pictures, and a failed retry leaving the next request unchanged.

## Notes

- Upstream has not released this commit; the version number follows our own sequence.
- Everything else is unchanged: page picture lists, the Bing fallback, bubble pictures, the Node updater, the not-official notice and NOTICE.
- Windows updates work as before; macOS and the portable build are downloaded by hand.
