# Coopanion v0.2.39

**Fix the Windows updater picking the Arm64 installer after Arm builds joined the release**

## Fixed

- **The Windows updater downloaded the Arm64 installer**: since 0.2.38 the release carries both x64 and Arm64 setups, and the updater took the first `.exe` in asset order, where `Coopanion-Setup-<version>-arm64.exe` sorts first; an x64 PC then downloaded the arm64 setup (and verified it against the wrong channel file). The installer is now chosen for the running processor: x64 takes `Coopanion-Setup-<version>.exe`, arm64 takes `…-arm64.exe`.
- **Verification reads the channel file of the same processor**: with an older API answer that states no sha256, x64 reads `latest.yml` and arm64 reads `latest-arm64.yml`, instead of checking an arm64 setup against the x64 digest.
- Two tests cover the choice: picking the setup by processor when both builds are in the release, and reading the processor's channel file when the answer states no digest.

## Notes

- Only `app/node-updater.cjs` and its tests changed. An installed 0.2.38 needs one manual install of 0.2.39 (auto-update on 0.2.38 picks the wrong file), after which updates work as usual.
